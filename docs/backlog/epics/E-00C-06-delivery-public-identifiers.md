## Why

E-00C-05 exposed the delivery REST edge, but the Codex DoD audit found the current public contract still leaks internal UUIDs such as `deliveryId`, `deliveryItemId`, `skuId`, `originLocationId`, `assignedUserId`, and `createdBy`.

ADR 0002 requires public APIs and URLs to use slugs, codes, or generated references instead of raw internal IDs. Delivery persistence currently has item-level `itemReference`, but no delivery-level public reference, so this cannot be fixed safely with a mapper-only change.

## Scope

1. Add a delivery header public reference strategy.
2. Backfill existing delivery rows with stable references.
3. Update delivery public contracts and route params to use public identifiers.
4. Resolve public identifiers to internal UUIDs inside route/service boundaries.
5. Update response mappers and query repositories to hydrate slugs/SKUs/references.
6. Update delivery platform-event payloads where delivery identity leaves the module boundary.

## Out of scope

- Frontend portal screens that consume the new delivery contract.
- Online-order source wiring.
- Broad cleanup of other modules that still expose raw UUIDs outside this delivery slice.

## Implementation notes

- Add a new reference sequence key for delivery headers, separate from the existing `delivery-item` key.
- Prefer a generated reference such as `DLV-00001` or a date-scoped equivalent; document the choice in the delivery schema docs.
- Keep service/repository internals free to use UUIDs after route handlers resolve public identifiers.
- Location and user public identifiers already exist as `locations.slug` and `users.slug`.
- Catalog variant public identifiers already exist as variant `slug` and `sku`.

## Definition of Done

- ADR 0002 compliance is evidenced by tests that reject or fail if public delivery DTOs include raw internal UUID fields.
- Route-level authorization still happens after resolving delivery origin from the server-side record.
- Existing E-00C-05 route tests are updated to the public-reference contract.
- `pnpm guard` passes.
